## MAJOR (3) — confirmed; none blocks on its own, each should be fixed or explicitly deferred with the reason written down

### M1 — The restored string/colour fields are unreachable from a physical keyboard, and typed characters land in the selected piece's X position
`src/editor/ensemble-editor.ts:3925` · `src/editor/schema-panel.ts:444` · lens: correctness · **confirmed** (severity was flagged uncertain; major upheld)

The repo's only `ui.fieldGroup` (ensemble-editor.ts:3924-3927) is built from `inputs.flatMap((i) => i.fields)`, and `inputs` is pushed to in exactly three places — the piece `vector3d` position, `euler3d` rotation and `vector3d` scale. Every `ui.inputField` from `schemaWidgets` goes into the panel's visible `fields` and into no group. In tosijs-3d 0.8.1's `keyboard.js`, `fieldGroup.attach()` increments a module-global that makes the window key listener return early, while `handleKey` routes only to the group's own `active` field; tapping an out-of-group field sets the module-global `activeField` but never moves `group.active`.

Reproduced end-to-end under happy-dom against the real 0.8.1 modules: focus X, tap the colour field (two lit carets), type `1`,`2`,`3` → the colour field's `handleChange` fires **zero** times and the vector commits `{x: 1123, y: 2, z: 3}`. With no prior group focus the characters are silently discarded. A control with no group attached records them correctly, so the group's presence is the cause.

The group is attached whenever a piece is selected, and the string fields only exist inside that same selected-piece panel — so they are shadowed 100% of the time they are visible. The on-screen-keyboard glyph route bypasses the group and still works, which is why this is major rather than a blocker. But the release's headline entry, "Strings are editable, including colours", is false for a physical keystroke, and the silent write into the piece's X position is data corruption.

**Before tagging, pick one:** include the schema panel's `InputField`s in the `fieldGroup` (same OUT-parameter shape the diff just added for `boundKeys`, and do the same in `_renderToolOptions`), or soften the changelog entry to say the fields are editable by tap/on-screen keyboard. Then add the `.pw.ts` that types into `ground.texture` on `standard-scene.json` and asserts the document changed — no test in the repo exercises the property panel today, so neither this nor the `boundKeys` fix has end-to-end evidence.

### M2 — `declaredConfig` silently drops undeclared feature keys on all three roads, is filed under Fixed rather than Breaking, and has no runtime or `validate` diagnostic
`src/format/registry.ts:298` (applied at `src/runtime/build.ts:311`, `:441`, `src/editor/ensemble-editor.ts:635`) · `CHANGELOG.md:262` · lens: correctness + blast-radius (two findings merged) · **confirmed**

The allow-list is justified as "the schema is already the exact list of what a feature accepts". For scene features that is not true: `pick()` (features-scene.ts:239-274) documents that WHICH properties an author sees is an *editorial* choice. Measured against the installed tosijs-3d 0.8.1 — terrain 17 of 30, water 8 of 22, ground 5 of 13, clouds 9 of 18, ambient 5 of 17, skybox 11 of 16, sun 6 of 15. Every unexposed key is now stripped with no warning, no console message and no `validate` problem (`validate` never inspects feature config; its only feature check is `unknown-feature` on the NAME).

Reproduced with the real registrations: `terrain {surfaceType:"torus", majorRadius:500, minorRadius:80, cylinderHeight:20, radius:1000}` → `{surfaceType:"torus", radius:1000}`. `majorRadius` is a genuine `b3d-terrain` attribute the bind would have spread through, so the panel offers a torus whose two defining dimensions the format now refuses to carry. Same shape for `water.normalMap`, `clouds.model`/`seed`, `ambient.rate`, `skybox.rayleigh`, `sun.shadowBias`.

**Sharper still, found during verification:** the link path boxes a scalar payload as `{value: cfg}` **before** narrowing, so any link registration carrying a schema now receives `{}` for the package's own documented scalar convention — `links:[{from,to,delay:1.5}]` with a schema declaring `delay` yields `cfg = {}` and `problems = []`, where 0.2.0 delivered `{value:1.5}`. `src/runtime/links.test.ts:69` registers no schema, so the suite is blind to it.

Mitigating and checked empirically: 0 keys dropped across all 7 shipped `static/ensembles/*.json` and manta-recon's 4 prefabs, and manta-recon's four registered features declare every key their binds read. The exposure is the next consumer, and the absence of any diagnostic when it happens. This is the release's own silent-no-op class — the one it fixes twice elsewhere — arriving through a security fix, while `pick()` one file over sets the house standard by `console.warn`ing on drift.

### M3 — The confirmed DOM-property-injection mechanism lives in tosijs's element creators and was fixed only locally: no upstream issue, no UPSTREAM.md row
`UPSTREAM.md:76` · `../tosijs/src/elements.ts` `elementProp()` · lens: blast-radius, **routed as ecosystem** · **confirmed**

The changelog states the mechanism as a property of the dependency ("a tosijs element creator applies unknown keys as PROPERTIES"), confirmed executing in real Chromium. `declaredConfig` closes it for this package's three roads and for nobody else. Verified during triage: `gh issue list` over all tosijs issues (1-42) and all tosijs-3d issues, plus searches for `innerHTML` / `untrusted` / `XSS` / `sanitize` across the owner's repos — **zero hits**. The nearest upstream record, tosijs#26, asserts the *opposite* runtime model ("an unknown prop is silently dropped at runtime"), and `elements.ts:6` opens "generating DOM elements without using `innerHTML` or other unsafe methods" while a props object can set exactly that.

One nuance the finding understates: the UPDATE road is this repo's own code — `updateAttrs` at `src/runtime/features-scene.ts:316` is literally `element[key] = value`. Half local, half dependency. The local allow-list is the right local fix and should stay regardless; what is missing is the signal outward.

## MINORS

### m1. The http-localhost exemption applies on any page, so a shared document can send plaintext GETs to a reader's local services (security, **confirmed**)
`src/format/url-policy.ts:84`. `urlProblem` accepts `http://localhost:9200/_shutdown`, `http://127.0.0.1:3000/admin/reset`, `http://127.1/`, `http://0x7f000001/x` and `http://[::1]/`, because WHATWG parsing normalises these to loopback before the `LOCAL_HOSTS` check. The check never looks at the page's own origin. Mixed-content blocking does not apply to loopback. The error text says a shared ensemble "cannot choose what a reader's browser … fetches", which this exemption contradicts.

Mitigating factors: the exemption is an owner decision from d89f9a3 and is documented. The rule is explicitly not a host allow-list, since `https://localhost` and `https://10.x` already pass, so the only thing the exemption adds is plaintext loopback. Recent Chromium Private Network Access rules may also add a preflight. The exemption predates this diff. **Owner call:** limit it in the loaders to pages whose `location.hostname` is local, or keep it and soften the wording.

### m2. The mountLibraries refusal branch (remove the stale mount, warn, refuse a non-string url) has no test that fails without it (correctness + security, merged, *unverified*)
`src/runtime/libraries.ts:82`. The only runtime url-policy test (`libraries.test.ts:176`, `mountedUrls`) fakes `getLibrary: () => null`, so `host.getLibrary?.(name)?.remove()` never runs. Only string urls are passed. The `console.warn` is not asserted. If someone deletes the removal line or moves it after `continue`, the suite stays green and the stale mount keeps rendering. That is the same report-versus-refuse drift that 0.4.0 has already been caught with once.

### m3. The completeness test and CHANGELOG claim to catch "any url-shaped built-in property", but the test is a name regex, top-level only (correctness, *unverified*)
`src/format/feature-urls.test.ts:250`. `URLISH` misses `uri`, `path`, `source`, `asset`, `hdr`, `env`, `icon`, `font` and `video`. The test reads only top-level `properties` and `x-accepts`, so it never sees a nested object property (the shape `lamp.settings` has). CHANGELOG.md says "a test now fails for any url-shaped built-in property that is neither marked nor explained", which overstates what the test does.

### m4. Link payloads are refused at runtime but never reported by validate, and a scalar payload skips the policy entirely (correctness, *unverified*)
`src/format/url-policy.ts:109`, `build.ts:450`, `validate.ts:431`. For an object link payload with a fetched key, `declaredConfig` drops the key silently, and validate's links loop checks only `from`/`to`. That breaks "refused and said, not dropped". A scalar payload goes to bind as `{value}` and never reaches `fetchedValueProblem`. No built-in link kind fetches, so only consumer registrations are exposed. This predates the diff, but the diff's docstring and commit title claim the class is closed.

### m5. No size delta, and no size for the game-import bundle (efficiency, *unverified*)
`bin/site.ts:12`. `bun run build` prints absolute doc-site sizes that Babylon dominates (iife 11321.1kb / 2745.6kb gzip). The reviewer had to build `bab1060` and HEAD side by side to get a delta: +0.5kb raw, +0.3kb gzip, which is justified. A leak of an editor or preset module into the format layer would be invisible against an 11 MB number.

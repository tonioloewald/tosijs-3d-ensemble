## MAJOR: confirmed, fix before the tag (cheap)

### M1. The https rule is bypassed by whitespace or control characters (correctness + security, merged)
`src/format/validate.ts:140-142`. `urlProblem` tests the **raw** string against `/^[a-zA-Z][a-zA-Z0-9+.-]*:/`. Anything that does not match is treated as "relative" and returns null. The WHATWG parser, which fetch, the loader and `new URL` all use, strips leading and trailing C0 control characters and spaces, and removes tab, CR and LF anywhere in the string. The verifier reproduced each of these returning **no** problem, as a library url and as a feature url (line 451 reuses the same function):

- `" http://evil.example/x.glb"`, `"\thttp://…"`, `"\nhttp://…"` and `"ht\ttp://…"` all resolve to `http://evil.example/x.glb`
- `"java\nscript:alert(1)"` and `"java\tscript:alert(1)"` resolve to `javascript:alert(1)`
- `" data:model/gltf-binary;base64,AA"` resolves to `data:`

The unpadded `http://…` is correctly rejected, so the gap comes only from parser normalisation. A generator that trusts `validate()` will emit these strings.

**Fix:** classify the url the way the consumer parses it, with `new URL(url, "https://relative.invalid/")`. If the result is at the sentinel origin, the url is relative. Otherwise apply the https/localhost rule to the parsed `protocol` and `hostname`. This also settles the `//host` nit. Add the strings above to `validate.test.ts` and `feature-urls.test.ts` as cases that must fail.
*Re-review scope: security + correctness over the remediation diff.*

### M2. The rule is never enforced on the path a reader loads through (correctness)
`src/runtime/build.ts:575`, `src/runtime/libraries.ts:71-97`, `src/runtime/ensemble-element.ts:~167`, `src/editor/ensemble-editor.ts:~1497`.

- `loadEnsemble`, `<tosi-ensemble>.load` and the editor's `load` all call `mountLibraries` **before** `buildEnsemble`, which is the first place `validate` runs.
- `mountLibraries` sets `url` on a `<tosi-b3d-library>` for any non-empty string.
- `buildEnsemble` records the problems and binds anyway, so a `starfieldData` or `ground.texture` value is still fetched.

A reader who opens a shared document therefore contacts whatever host the document names. No test asserts that mount or build refuses a bad URL.

**Fix, pick one:**
- **(a) Enforce.** Export `urlProblem`, or an `acceptableUrl` predicate, from the format layer. The tree-shaking boundary is unaffected, because runtime already imports format. Then have `mountLibraries` skip bad libraries and have feature binds skip bad fetched keys. Report each skip in `problems`, and add a test that an `http` library creates no element. This keeps `validate` non-throwing, as the invariant requires.
- **(b) Declare it advisory.** Do this together with M3.

Option (a) matches the stated threat model.

### M3. The docs claim a protection the runtime does not provide (blast-radius + security docs, merged; the security and blast-radius verifiers rated this minor)
These texts all read as a guarantee to anyone who upgrades:

- CHANGELOG: "A library url must be https", "A feature's fetched URLs must be https too", and "…could point a reader's browser at any host the moment they opened it"
- `urlProblem`'s error text: "so that a shared ensemble cannot choose what a reader's browser executes or fetches"
- the TODO closure in 4b0de72

In fact only a generator or editor that reads `problems` is protected. Mitigating factors: https pages already block `http` fetches as mixed content, and even an enforced rule allows **any** https host. If you choose M2(a), update the wording to match. If you choose M2(b), reword everything to "validate **reports** an error when…; loaders do not enforce it" and reopen the TODO item for readers.

## MINOR / NIT: follow-ups (not blocking)

- **m1 (unverified)**: cloudDeck `follow`/`shadows` boolean → `'on'/'off'` mapping (`src/runtime/features-scene.ts:1372`, `deckToElement`) is new runtime behaviour with no test that fails without it; regression = an editor checkbox that does nothing.
- **m2 (unverified)**: The consumer bundle grew with nothing reporting it. The game entry went 8.2 → 9.35 kB gz (+13.7%), and the format kernel `validate.ts` went 2.25 → 2.77 kB gz (+23%). The growth looks justified (URL checks, `fetchedKeys`, cloudDeck, moon, wider sky/terrain picks), but the CHANGELOG has no line for it. The ceiling test (`src/tree-shaking.test.ts:121`, 4000 < gz < 14000) prints nothing, and its "8.5 kB when written" comment is stale.
- **n1 (unverified)**: A protocol-relative `//evil.example/x.glb` counts as relative. On an http page it is plaintext to a third-party host. The M1 fix resolves it; otherwise document the behaviour.
- **n2 (unverified, practices)**: `.github/workflows/publish.yml:69` checks out `tosijs-coding-practices` at its default branch without pinning. `release-doctor`, `attest --verify-shipped` and publish-smoke then run whatever that repo's HEAD holds on release day, against an attestation made by the local checkout. The file is a copy of the practices template ("copy it unchanged; fixes land there"), so the fix belongs upstream in the practices repo.

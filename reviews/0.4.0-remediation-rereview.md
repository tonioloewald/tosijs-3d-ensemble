## BLOCKER (1)

### B1. An array-wrapped feature url passes both validate and declaredConfig, and the element fetches it (correctness, **confirmed**)
`src/format/registry.ts:370`, `src/format/validate.ts:389`

- **Reproduced at HEAD:** `{ skybox: { starfieldData: ["http://evil.example/sky"] } }`. `validate(doc)` returns `[]`, and `declaredConfig(skybox, cfg)` returns the array unchanged. The plain-string version is correctly refused and dropped. An object with a `toString` behaves the same way as the array, so the problem is general and not specific to arrays.
- **Why it fetches:** features-scene assigns cfg to the element unchanged. `node_modules/tosijs-3d/dist/b3d-skybox.js:1403` does `String(attrs.starfieldData ?? '')`, which yields `"http://evil.example/sky"` (truthy), so the data cube loads. An array is valid JSON, so a shared document can carry it.
- **Cause:** both copies of the predicate guard with `typeof value !== "string"` and treat a non-string as not a url, so it skips the check. This fails open. Libraries are not affected, because `new URL()` stringifies the array and refuses it.
- **Not yet observed:** the actual network request in a browser. The data flow is confirmed as far as the upstream `String()` call.
- **Fix:** one helper in `url-policy.ts`, e.g. `fetchedUrlProblem(registration, key, value)`, that treats **any non-empty, non-string value for a fetched key as refused** (`unsupported-feature-url`), or checks `String(value)`. Call it from both validate and declaredConfig, which also closes N1. Add `["http://evil.example/x"]` and `{}` rows to the BYPASSES table in `src/format/feature-urls.test.ts`.
- **Re-review scope:** correctness + blast-radius over the remediation diff only.

## MAJOR (1): confirmed; fixing it is a condition of GO

### M1. The built-in `sound.url` is never checked (security, **confirmed**, adjusted blocker → major)
`src/runtime/features-scene.ts:1085`

- `url: { type: 'string', title: 'Audio file' }` has no `format: 'uri-reference'` and no `x-fetched`, so `fetchedKeys` (`registry.ts:333`) never sees it. `http://evil.example/a.mp3`, `//evil.example/a`, `data:…` and `javascript:…` all validate clean, pass `declaredConfig` unchanged, and reach `new BABYLON.Sound(…, attrs.url, …)`.
- This is our own built-in feature, not a consumer opt-in, so the CHANGELOG's "Enforced" claim is false for a feature we ship. It is major rather than blocker because the fetch is audio with no script-execution path. It is the same class as the prior run's M1–M3.
- **Fix:** add `format: 'uri-reference'` to `sound.url`, and add `sound.url` to the BYPASSES table. Add a **completeness test** that walks every registered built-in feature (scene, combat, world) and fails on any url/src/texture/map/data-named property missing from `fetchedKeys`, so an unmarked field shows up as a test failure instead of silently going unchecked. Ask tosijs-3d for a `sound` entry in `sceneSchemas` (see UPSTREAM below); keep the local marker until it exists.
- **Re-review scope:** correctness + security over the remediation diff.

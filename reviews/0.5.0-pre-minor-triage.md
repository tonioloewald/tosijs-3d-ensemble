# Pre-release triage: tosijs-3d-ensemble, v0.4.0 → HEAD ("a patch for manta")

**Verdict: BLOCK as 0.4.1. The code is ready to ship as 0.5.0 once the version is fixed and the terrain major is decided.** One confirmed blocker (found three times), one confirmed major, two confirmed minors, and three unverified leads (one minor, two nits).

Cycle flag: not triggered. The blocker is a version-level issue new to this cycle. It does not sit in code that remediated an earlier blocker (checked `reviews/`).

## Short answer to "can we cut a patch for manta?"

Yes, manta can have its release, but it has to be **0.5.0**, not 0.4.1. HEAD is breaking by this repo's own docs. Manta pins `"tosijs-3d-ensemble": "0.4.0"` exactly and already runs tosijs-3d 0.9.0, which is outside 0.4.0's `^0.8.4` peer. It has to edit its dependency line either way, so a minor costs manta nothing more than a patch would. A real 0.4.x patch would need a branch off `v0.4.0` that cherry-picks only the non-breaking fixes. That is not what HEAD contains, and it would not fix manta's peer conflict anyway.

## Blockers

### B1. HEAD is breaking, so it cannot ship as a patch. Cut 0.5.0. (confirmed, 3 lenses: correctness, docs, blast-radius)
`package.json:3`, `CHANGELOG.md:6`, `MIGRATING.md:208`

- CHANGELOG `[Unreleased]` opens with **⚠️ Breaking**:
  - the tosijs-3d peer moves from `^0.8.4` to `^0.9.0` (under 0.x caret rules this excludes every 0.8.x);
  - the tosijs peer moves from `^1.10.1` to `^1.10.3`;
  - `biomeTemperature` changes meaning;
  - unset fields now render at the schema default: 47 fields across 13 features. For example, ground goes from 4 m to 400 m, sun cascades from 0 to 2, and fog from linear to exp2.
- MIGRATING.md:208 is already titled "Upgrading from 0.4 to 0.5 (unreleased)". `features-scene.ts:565` reasons from "every ensemble saved before 0.5.0".
- **What 0.4.1 would break:**
  - any `^0.4.0` consumer would pick up an unmet peer and a scene that renders differently, with no code change on their side;
  - the shipped MIGRATING would point readers at a 0.5 that does not exist.
- **Fix:** bump to 0.5.0 and turn `[Unreleased]` into `[0.5.0]`. Then bump manta's exact pin to 0.5.0. Re-review scope: Tier 0 only (the version string and the CHANGELOG heading).

## Major (confirmed; decide before tagging)

### M1. terrain: the new `baseHeight: 0` default overrides the piece's y, so moving a terrain vertically does nothing
`src/runtime/features-scene.ts:1379`

- The bind is `b3dTerrain({ baseHeight: ctx.at[1], ...terrainConfig(cfg) })`.
- `build.ts:313` now passes `effectiveConfig`, which always fills `baseHeight: 0`. Because cfg is spread after `ctx.at[1]`, the default wins.
- The skeptic reproduced it: a terrain at `[0,-140,0]` builds at 0.
- The update path at `:1266` writes the 0 again on every rebuild, so dragging a terrain up or down in the editor silently snaps it back.
- It is latent today: every shipped terrain sits at y = 0, and manta has none. But it breaks documented behaviour, and the fix is a few lines.
- **Fix:** give `baseHeight` no schema default (a `pick()` override with `default: undefined`, or drop it from the picked keys). Add a pure-helper unit test that a terrain at y = 25 with no `baseHeight` binds with 25.

This does not block on its own (majors are not promoted). Recommendation: fix it in the 0.5.0 commit, since a control that does nothing is exactly what this project's rules forbid. Otherwise file it.

## Minor

- **m1. (confirmed, docs) Schema defaults now reach EVERY feature's bind, and nothing documents it.** This includes combat, world and consumer features such as manta's radar, spawner and patrol-zone. Defaults nested inside an object property (`radar.boost.*`) are *not* applied. The skeptic checked every bind fallback in combat, world and manta: all agree with their schema defaults, so no behaviour changes today. The gap is documentation only.
- **m2. (confirmed, correctness) The standalone `schemaPanel` rebuilds itself on every section fold** (`src/editor/schema-panel.ts:656`).
  - Each fold leaks a panel's worth of box observers (tosijs-3d#100), and there is no `_tracked` release hook.
  - `replaceWith` does nothing on a panel with no parent (one rendered to an in-scene surface).
  - The caller keeps a reference to the stale panel.
  - Reachable only through the `./*` subpath export; the editor itself is unaffected.
- **m3. (unverified, docs) The defaults-change docs disagree with themselves.** "Two things change" heads three bullets. The MIGRATING table omits `camera` (and `weatherCell`). The "47 fields across 13 features" count was measured on tosijs-3d 0.8.9 and is pinned by no test.

- **Manta as a consumer was not verified.** Nobody ran manta against HEAD. The skeptics read manta's feature fallbacks (they agree with its schema defaults), but its four ensembles were not loaded.
- **The browser lanes were not run** (see Gates not done). The new weather, wind and AO features are covered only by those local Playwright lanes. Combat and world features remain unverified in a browser, as CLAUDE.md already says.

- **Not run by any lens:** `bun run build`, because it rewrites the tracked `docs/` and `dist/`. The docs lens built from a scratch archive instead.

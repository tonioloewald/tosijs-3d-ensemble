## Findings

### Minor (correctness)

1. **(unverified) Editor `load()` JSDoc promises more than the code checks.** File: `src/editor/ensemble-editor.ts:1563`. The JSDoc says `load()` rejects on "a body that is not an ensemble" and leaves the open document alone. In fact, any JSON body is accepted: a `{"error":"not found"}` sent with status 200 replaces the author's document silently. `fetchEnsembleData` (`build.ts:575-580`) rejects only non-OK responses and non-JSON bodies. Fix: add a minimal shape check in `fetchEnsembleData` (the body must be an object with a `pieces` array), which fixes all three loaders at once. Otherwise, narrow the docs to "a failed fetch or a non-JSON body". Either way, add a test.
2. **(unverified) The `schemaPanel` fold release, the headline of the CHANGELOG leak fix, has no test.** File: `src/editor/schema-panel.ts:725`. No test calls `schemaPanel()`. Removing `boxes.release()` from `repaint`, or passing `options` instead of `tracked`, still leaves the suite green. Fix: add a `schema-panel.test.ts` case that counts live `observe` subscriptions across two folds.
3. **(unverified) A discarded `schemaPanel` still leaks its observers.** File: `src/editor/schema-panel.ts:699`. The fix covers folds only. A panel that is thrown away (inspector closed, or a new selection builds a new panel) keeps one listener per bound widget, which is the tosijs-3d#100 class of leak. The CHANGELOG line "leaked box observers" reads as fully fixed. Fix: expose a `release()`/dispose hook on the returned panel. At minimum, scope the CHANGELOG to "on every section fold" and note that discarding a panel still leaks until #100 lands.

### Nit

4. **(unverified, correctness) Escaped backticks and an orphaned JSDoc block.** `` \` `` renders literally in the `/*# */` doc block at `ensemble-editor.ts:53` ("Moving pieces"). The same pattern appears in JSDoc at `build.ts:562`, `schema-panel.ts:377-381`, `registry.ts:401-403` and `ensemble-editor.ts:1563`. Separately, `load()` has two stacked `/** */` blocks, so the hover text loses the generation-counter rationale. Fix: use plain backticks, and merge the two blocks or turn the rationale into a `/* */` comment.
5. **(unverified, blast-radius) The vacuous test baseline has now bitten twice.** File: `tests/rapid-edits.pw.ts:88`. The "editor loaded" predicate passes as `0 >= 0` against the editor's empty start-up state. It is hand-rolled in about a dozen `.pw.ts` files and was patched inline here, as it was before 0.4.0 in reparent. This is test-only, so nothing ships with it.

### Refuted finding (not a defect, noted for depth)

A reviewer claimed the refused-url clear might leave the old starfield up. Upstream code refutes this. `_buildStarfield` always calls `_disposeStarfield()` first, and the `""` value reaches the element through `Object.assign` in `features-scene.ts:532`. The truth was discoverable, so there is no docs gap. The only residue is test depth: no scene test watches the sky clear.

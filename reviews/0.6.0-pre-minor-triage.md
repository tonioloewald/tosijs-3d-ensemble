## Fix before the tag (verified majors)

- [ ] **(correctness) Stretch → uniform 1 leaves the piece stretched.** `src/runtime/node-transform.ts:80`
  - **Cause:** `scaleElement`'s uniform branch sets `element.scale = 1`, which it already is. tosijs's number setter queues a render only when the value changes, so the node keeps `[2,1,4]` while the document says 1. The same happens when a uniform scale is removed (`piece.scale ?? 1`). This affects the editor only.
  - **Fix:** when a stretch was recorded, write the node directly (`applyScale(element.mesh, v)`) or call `render()`.
  - **Clears when:** a unit case goes from `[2,1,4]` to `1` and asserts the node reads `1,1,1`. Its stub's setter must render *only on change*, like tosijs's does. The test must fail with the fix reverted.
- [ ] **(correctness) An in-place `at`/`rot`/`scale` edit moves the body but leaves positional features behind.** `src/editor/ensemble-editor.ts:697` (`_applyFeatureUpdates`)
  - **What breaks:** on a mesh piece carrying `turret`, `launcher`, `trigger`, `interactive` or `door`, the feature stays at the old `ctx.at`. The door's rest pose also stays at the old position, so animating it snaps the door back. A reload disagrees with the editor.
  - **Narrower than first stated:** a mesh-less light or sound piece is its own body and moves correctly.
  - **Fix:** apply in place only when the piece has no features, or only features that do not read `ctx.at`, `ctx.rot` or `ctx.scale`. Otherwise return false and rebuild. Give the drag-release (`rebuild:false`) path the same treatment.
  - **Clears when:** a test moves a mesh piece carrying `turret` (or `trigger`) through `edit()` and asserts the feature element's x/y/z equal the new `at`. It must fail with the fix reverted.
- [ ] **(docs) MIGRATING's 0.5→0.6 section names the peer as `^0.10.8`.** `MIGRATING.md:257,259`
  - **Conflict:** `package.json` and the CHANGELOG say `^0.10.9`, and planet↔terrain links need 0.10.9.
  - **Fix:** change both mentions to `^0.10.9` / `0.10.9`, and note that the links need it.
  - **Clears when:** `grep -n "0.10.8" MIGRATING.md` returns no hit in the 0.6 section. Better: add a release-doctor or unit check that the newest "Upgrading from" section names the same tosijs-3d range as `peerDependencies`.

- [ ] Optional lesson for `practices/model-priors.md`: a tosijs attribute setter does **not** re-render when the value is unchanged.

## Fix before the tag (verified majors)

- [ ] **Editor `load()` builds nested refs with no base, so reloading the same document loses its nested pieces.** `src/editor/ensemble-editor.ts:~2028`. The setter rebuilds synchronously while `_loaded` is still null, so nested refs resolve against the page: a 404 is fetched and recorded in `_nestedTried`. The first load works only because the doc-write observer happens to rebuild; a load of an identical document triggers no rebuild. *Fix:* set `_loaded` before `this.ensemble = data`, or pass the url into the build. Have `load()` collect nested documents and mount libraries before the first build, as `loadEnsemble` does. *Check:* a `.pw.ts` that calls `load()` twice on the same url and asserts the `rig-a/deck` piece is still present, and that no page-relative fetch was sent.
- [ ] **Re-drilling after an unsaved Back shows the child as clean (unsaved edits read as saved).** `ensemble-editor.ts:~2716`. popOut caches the edited child in `_nested`, and drillIn then uses that copy as `_loaded.json`, which `_linkLoaded` stores as `_savedJson`. *Fix:* keep each child's last-saved JSON separate from the working copy, recorded at fetch and on save, and use it as `_loaded.json`. Or carry savedJson in the context. *Check:* add to `nested-editor.pw.ts`: drillIn, edit, popOut without saving, drillIn again, assert `dirty === true`.
- [ ] **Opening another document while drilled in leaves `_contexts` in place, and Back then puts that document in as the nested child.** `ensemble-editor.ts:547` (setter), also `newEnsemble`. This affects Open, openFromStore, openRevision, load() and New. *Fix:* the ensemble setter clears `_contexts` (plus `_nested` and `_nestedTried`), and New inside a drill either refuses or clears the stack. *Check:* test that drills in, opens another document, then asserts `nestPath.length === 1` and that the Back button is absent.
- [ ] **collectNested has no in-flight dedupe and no fan-out or expansion budget** (security plus efficiency, merged). `src/runtime/build.ts:~633-671`. A shared child is fetched once per path, so requests grow as k^depth. Measured: 10 x 4 refs gave 50 fetches where 2 were needed, and F=6, D=6 gave 55,986 fetches and 46,656 flattened pieces. This makes a hostile shared document a reader-side DoS and a request amplifier against any https host, through loadEnsemble, `<tosi-ensemble>` and the editor. *Fix:* use `Map<key, Promise<Ensemble|undefined>>` for in-flight fetches, dedupe refs per document, and walk each key once. Add a fail-closed `MAX_FLAT_PIECES` (and optionally a cap on distinct documents) that reports a `nested-too-large` error. *Check:* a unit test with a counting `fetchDocument` that asserts fetch count equals the number of distinct urls, plus a fan-out bomb test that asserts refusal. Re-review scope: security plus correctness over the nest.ts / build.ts diff.
- [ ] **The docs never say how code loads a nested document.** `src/format/nest.ts:7`, and the Building page in `build.ts`. A host calling `buildEnsemble` directly gets a `nested-missing` warning that reads like a missing file. *Fix:* add a "Loading it" section to the nest page (loadEnsemble and `<tosi-ensemble src>` fetch children; a direct host passes `nested: await collectNested(doc, { base })` and `base`; an assigned document resolves against the page). Add `nested`/`base` to the Building example. Make the `nested-missing` message name `BuildOptions.nested` / `collectNested`. *Check:* a test asserting the nested-missing message contains `collectNested`, and the build's doc checker staying green.
- [ ] **x-piece-ref and x-widget:"ref" are two unconnected markers.** `src/format/nest.ts:25`. Rename uses one and nesting uses the other. A consumer feature marked only `x-widget:"ref"` resolves to the parent's piece once its ensemble is nested. `terrain.planet`, `planet.terrain` and landform `terrain` carry only `x-piece-ref`, so rename skips them. *Fix:* derive one marker from the other (or have both code paths accept either), document x-piece-ref on the Registry page, and qualify the nest page's "can never" claim. *Check:* a test that registers a consumer feature with only `x-widget:"ref"`, nests it and asserts the ref is prefixed, plus a test that renaming a piece rewrites `terrain.planet`.
- [ ] **Scrubbing a nested piece's transform rebuilds the whole scene on every change.** `ensemble-editor.ts:812` (`if (piece.ensemble) return false`). This brings back the "REBUILT THE SCENE EVERY FRAME" regression for nested pieces; the children flicker while you scrub. The lens rated it minor and the verifier confirmed it at minor, but it is listed here because it was verified. *Fix:* write the live transform of the nesting piece through to its children (they are in `built.pieces` under `id/`) and rebuild only on release. If that is deferred, record it in the CHANGELOG as a known 0.8 cost and move it to TODO.md. *Check:* a `.pw.ts` that scrubs the rotation of a nested piece and asserts the build generation does not advance per frame.

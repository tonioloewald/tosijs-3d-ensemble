## Fix before the tag

- [ ] **Undoing the first effect commit leaves the open effect tool, and the scene, playing the undone recipe, and the next commit writes it back.** `src/editor/ensemble-editor.ts:3007` (`_syncEffectTool`). *(major, confirmed)*
  - **What happens:** undo restores a document where `cfg.recipe` is undefined. The guard `if (cfg.recipe && …)` then skips updating the tool. The piece's own effect is set aside, so the tool's stale recipe is the only effect playing. The next gesture commits the tool's whole recipe, which brings the undone edit back. A `preset` change made in the panel while the tool is open is ignored for the same reason.
  - **Fix:** when `cfg.recipe` is absent, set `tool.handle.api.recipe = effectPreset(cfg.preset)`. This is the same fallback `editEffect` uses.
  - **Check that clears it:** extend `tests/effect-tool.pw.ts` to commit, undo, and then assert that the tool's `api.recipe` deep-equals `effectPreset('geyser')` and that the document has no `recipe`. Then change `preset` with the tool open and assert the tool follows. The new assertion must fail with the fix reverted.

## Follow-ups by destination

### This repo's `TODO.md` (correctness / dryness)

- [ ] **(unverified, minor)** While the effect tool is open, moving the piece or editing its effect fields does nothing visible (`ensemble-editor.ts:3007`).
  - **Problem:** `tool.node` is never moved to follow the piece. Panel edits to activity, scale and ground go through `updateAttrs` to the element that `_setAsideEditedEffect` has already detached. That is a control that does nothing.
  - **Fix:** reposition the node from `_liveOrigin(built)`. Then either forward those fields to the tool, or disable them while `editingEffect === id`.
- [ ] **(unverified, minor)** `closeEffect()` rebuilds by itself, so callers that are already rebuilding end up with nested or double rebuilds (`ensemble-editor.ts:216`).
  - **Where it happens:** the `ensemble` setter (`_loadMissingNests` fetches the same nested documents twice), `drillIn`, `popOut`, and `_syncEffectTool` inside `rebuild()`. The rebuilds are idempotent, so this is wasted work, not a corrupt scene.
  - **Fix:** add a `{ rebuild?: boolean }` option and pass `false` from the callers that are already rebuilding.
- [ ] **(unverified, minor; reported by both correctness and blast-radius)** `rewriteFetched` is a line-for-line copy of `deepFetchedProblems`' schema walk, and the copies have already drifted (`src/format/url-policy.ts:263` and `:567`).
  - **How they differ:** `rewriteFetched` has no `x-keywords` exemption, so a keyword inside nested `x-data` would be rebased into a url that does not exist. The top-level rebase in `nest.ts` does skip keywords. The two copies also treat a matched union branch differently.
  - **Impact today:** none, because the effect recipe schema has no `x-keywords`.
  - **Fix:** write one `visitFetched(schema, value, visit)` walker and implement both functions on it. Make the rewrite honour `x-keywords`. Add a nest test that puts a keyword inside `x-data` and checks it comes through unchanged.
- [ ] **(unverified, minor)** `_nestBounds` caches a partial measurement taken before every child has finished instantiating (`ensemble-editor.ts:2711`). The selection marker then draws the wrong box until the next rebuild.
  - **Fix:** cache only once every child body has a mesh, or re-measure for a few frames after a build.
  - **Test:** add a happy-dom test that the cache is invalidated by a new `built` and by `_moveNestInPlace`.
- [ ] **(unverified, nit)** `TosiEnsemble` keeps a stale `_flattened` when the same object is mutated in place and assigned again, and the sync build path runs (`src/runtime/ensemble-element.ts:736`). It then builds the old flat pieces. **Fix:** clear `_flattened` in `_setData` and in the `ensemble` setter.
- [ ] **(unverified, nit)** Running the scene lane deletes the committed `docs/` tree from the working copy, because the Playwright webServer is the dev server.
  - **Now:** git status is clean, so the tree has been restored. Re-check `git status` after `release:attest` and before tagging, and run `git checkout -- docs` or `bun run build` if needed.
  - **Longer term:** point the dev server's output somewhere other than the committed `docs/`.

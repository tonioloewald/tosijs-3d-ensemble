## Findings by severity

### Minor, verified

1. **Effect tool: after a recipe swap the player's activity diverges from the document** (`src/editor/ensemble-editor.ts:3033`, correctness, CONFIRMED). The recipe setter's `adopt()` resets `player.activity` to the recipe's own value, for example 0.5 for volcano. `_syncEffectTool` skips re-applying the document's activity (0.25) because `tool.activity` did not change. The panel then shows a value the player is not using. This is the failure #3437 set out to remove. Fix: clear `tool.activity` when the recipe is reassigned, and add a step to `tests/effect-tool.pw.ts` that changes the preset with activity set and asserts the player's activity.
2. **A nest whose child never gets a mesh re-walks every child's hierarchy every frame** (`src/editor/nest-bounds.ts:90`, efficiency, CONFIRMED). `measure()` refuses to cache while any child is pending. A missing library node, a rejected `lib.ready` or an unregistered library leaves the child pending forever, so the walk #3423 removed comes back for as long as the nest is selected. The cost is bounded and equals pre-#3423 behaviour. Fix: cap or back off the retry, or clear the cache when the library settles.
3. **store.ts says `editor.dirty` stays true after a failed Save, which is false for a never-stored document** (`src/editor/store.ts:33`, docs, CONFIRMED, adjusted to minor). `_isDirty()` needs a non-null `_savedJson`, and New, Open file and a `src` with no `idFor` all leave it null. A host guarding unload on `dirty` would lose the document. The getter's own JSDoc is accurate, so this sentence is the one that overreaches. Fix: narrow the sentence, or make an edited never-stored document count as dirty. Pin the choice with a `store.pw.ts` case.
